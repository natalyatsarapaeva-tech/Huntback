# Huntback

Поиск работы для кандидатов уровня middle management и выше — **включая места,
где вакансия ещё не опубликована**.

Приложение раньше называлось «Периметр». Слово «периметр» осталось в продукте,
но уже только как термин: это поле профиля — набор ролей, которые интересуют
кандидата, и второй шаг онбординга.

Полное ТЗ: [`docs/huntback-spec-v1.2.md`](docs/huntback-spec-v1.2.md).
Ссылки вида «§10.4» в коде и комментариях — на него.

> **Статус: Этап 0 + ядро Этапа 1.** Чистое ядро написано и покрыто тестами,
> воркер и SPA написаны и проходят строгий TypeScript, интерфейс собирается и
> проверен в браузере. Не сделано: деплой (нужны аккаунты Cloudflare/Google/
> OpenAI), Google Sheets (§11), экспорт DOCX/PDF (§10.5), очередь прогонов
> проверена только по коду.

## Что здесь лежит

```
core/      чистое ядро: ни сети, ни базы, ни DOM — только логика ТЗ
worker/    Cloudflare Worker: OAuth, сессии, D1, вызовы модели
web/       SPA на React + Vite
scripts/   layout-check.mjs — критерий приёмки 9 автоматически
docs/      ТЗ
```

### `core/` — почему он первый

Вся детерминированная логика ТЗ вынесена в модули без единой зависимости и
покрыта тестами на `node --test`. Дисциплина перенесена из `twin-things` (45
тестов) и `Help_me_clean` (157 тестов), но здесь у неё есть преимущество,
которого у них не было: воркер и фронтенд на одном языке, поэтому **ядро
импортируют оба**. Счётчик слов в письме на экране и проверка длины на сервере —
буквально одна функция (критерий приёмки 12).

| Модуль | Что внутри | Критерии приёмки |
|---|---|---|
| `score.ts` | `100 × Σ(w·s) / Σ w`; блокер не обнуляет совпадение | 5 |
| `blockers.ts` | четыре измерения §10.4, снятие блокера **без вызова модели** | **5b** |
| `checks.ts` | 13 кодовых правил §10.10 | **6c, 6d** |
| `audit.ts` | метрики чек-листа §10.4a | 5a |
| `dedup.ts` | `company_key` + Левенштейн по роли | 7 |
| `budget.ts` | месячный лимит, 80% / 100%, лимиты прогонов и писем | — |
| `sanitize.ts` | приведение ответов модели к закрытым спискам | 5, 6 |
| `text.ts` / `json.ts` | словоформы, `source_hint`, терпимый разбор JSON | 5, §16 |

### `worker/` — единственное место с секретами

Отдельный деплой и **отдельный project-ключ OpenAI**. Общий
`task-intake-worker` семейства Twin переиспользовать нельзя: он защищён только
проверкой Origin, а здесь в промптах резюме и расход считается на пользователя
(§4.3.1, критерий приёмки 13).

Контракт вызова модели один на все операции (`ai.ts`):

```
schema → parse → retry(1) → sanitize → validate → log(usage)
```

429/503 → три попытки с задержкой 2/8/20 с → модель ступенью ниже с пометкой
`degraded`. Неудачные вызовы пишутся в `usage_log` тоже: иначе «$0» означает
и «дёшево», и «ничего не работает» (§4.3.2).

Промпты, пороги, стоп-листы и карта моделей — **данные**, а не константы:
дефолты в коде, переопределения в таблице `config`, правка через
`/api/admin/config`. Без этого §19 «ревизия порогов через две недели» и
Приложение Б «список пополняется» остались бы декларациями.

### `web/` — интерфейс

Палитра: пыльная роза (действие, акцент, совпадение) и синевато-серый
(структура и текст), белого около половины площади. Цвет появляется только там,
где он что-то значит; единственный по-настоящему тревожный цвет в приложении —
жёсткий блокер.

Онбординг — четыре шага: резюме → периметр → подтверждение фактов → поля,
снимающие сомнения. Третий шаг честно говорит, что это разовая работа и что
неподтверждённые факты не попадут никуда.

## Как довести до рабочего состояния

Пошаговая инструкция с нуля — [`SETUP.md`](SETUP.md): Cloudflare (D1, KV,
очередь), OpenAI (ключ проекта и лимит), Google Cloud (вход через Google), и
проверка по сценарию. Firestore не нужен — Huntback на Firebase не построен
(§4.2.3).

## Витрина на GitHub Pages

`https://natalyatsarapaeva-tech.github.io/huntback/` — публикуется автоматически
из `main` через `.github/workflows/pages.yml`.

**Что там опубликовано: только интерфейс.** Pages отдаёт статику, а серверная
часть Huntback — это Cloudflare Worker с D1, OpenAI и Google OAuth; ничего этого
на Pages нет и быть не может. Поэтому витрина собирается с `VITE_DEMO_ONLY=1`:
экран входа не показывает кнопку Google (она вела бы в 404), а ведёт в демо.

Демо честное в одном важном смысле: подделаны только модель и база. Аудит
профиля, совпадение с местом, жёсткие блокеры и проверки документов считает то
же ядро `core/`, что работает в приложении. Компании и люди в демо вымышлены —
это требование, а не стилистика: выдуманный сигнал про существующую компанию
на публичной странице был бы опубликованной неправдой о действующем бизнесе.

Одна настройка в репозитории: **Settings → Pages → Source = «GitHub Actions»**.
Workflow перед публикацией гоняет тесты ядра и типы, поэтому витрина не уедет
зелёной при красной логике.

## Запуск

```bash
npm install
npm run verify        # тесты ядра + строгий TypeScript всех трёх пакетов + сборка
npm run dev           # SPA на :5173; /api проксируется на воркер :8787
```

Интерфейс открывается **без бэкенда**: на экране входа есть «Посмотреть на
демо-данных». В демо подделаны только модель и база — аудит, совпадение,
блокеры и проверки документов считает настоящее ядро, поэтому демо не врёт.

Проверка вёрстки (критерий приёмки 9) — на собранном `web/dist`:

```bash
npx vite preview --port 4173 &     # или любой статический сервер на dist
npm run check:layout
```

### Воркер

```bash
cd worker
wrangler d1 create huntback                 # id вписать в wrangler.toml
wrangler kv namespace create KV             # id вписать в wrangler.toml
npm run migrate                             # применить migrations/
wrangler secret put OPENAI_API_KEY          # отдельный project-ключ!
wrangler secret put GOOGLE_CLIENT_ID
wrangler secret put GOOGLE_CLIENT_SECRET
wrangler secret put TOKEN_ENC_KEY           # 32 байта base64
wrangler secret put SESSION_PEPPER
npm run deploy
```

## Что проверено и чем

| Что | Чем |
|---|---|
| Логика ТЗ | `npm test` — 72 теста, без сети и без ключей, ~0,3 с |
| Типы | `npm run typecheck` — strict во всех трёх пакетах |
| Сборка SPA | `npm run build` |
| Вёрстка на 375–1280 px | `npm run check:layout` — вылеты и цели меньше 44 px |
| Экраны | headless Chromium, снимки всех состояний |

Не проверено вживую: деплой воркера, реальные вызовы OpenAI, Google OAuth,
очередь прогонов. Для этого нужны аккаунты, которых у сборки нет.
