# Huntback — настройка с нуля до работающего приложения

Инструкция для человека, у которого пока нет ни одного из аккаунтов. Шаги идут
в том порядке, в котором их можно выполнять: ни один не требует того, что
делается ниже.

После каждого шага написано **«как понять, что получилось»** — не переходите
дальше, пока не сходится.

---

## Firestore не нужен

Huntback на Firebase не построен. В ТЗ (§4.2.3) Firebase отклонён целиком:
данные реляционные и локальные для одного пользователя, поэтому база — D1, а
авторизация — свой OAuth, а не Firebase Auth. Firestore нужен трём другим
приложениям семейства (twin, twin-things, Help_me_clean), здесь его не касаемся.

Работа только в трёх местах: **Cloudflare**, **Google Cloud**, **OpenAI**.

---

## Шаг 0. Решение про деньги — принять до начала

| Что | План | Сколько |
|---|---|---|
| Workers, D1, KV | бесплатный хватает | 0 |
| **Queues** (фоновый поиск мест) | **только платный Workers** | **$5/мес** |
| OpenAI | оплата по факту | $5–9 в активный месяц поиска (§10.9) |
| Google Cloud | OAuth бесплатен | 0 |

**Очереди — единственное, что упирается в платный план.** Без них не работает
одна кнопка — «Найти места» (фоновый прогон поиска). Всё остальное работает:
ручное добавление вакансии по ссылке или тексту, аудит профиля, разбор ожиданий,
резюме, письма, проверки.

Важно: воркер сейчас **не задеплоится** без существующей очереди — привязка
`RUNS` указывает на неё. Поэтому решение развилочное:

- **Беру платный план** → делайте шаг 3 как написано.
- **Пока без платного** → скажите мне, я уберу очередь за флаг: «Найти места»
  отключится с honest-сообщением, остальное поедет на бесплатном плане.

## Шаг 1. Cloudflare: аккаунт и вход

1. Регистрация на `dash.cloudflare.com` (карта не нужна для бесплатного плана).
2. В терминале, из корня репозитория:

```bash
npm install
npx wrangler login
```

Откроется браузер, надо подтвердить доступ.

**Как понять, что получилось:** `npx wrangler whoami` печатает вашу почту и
идентификатор аккаунта.

---

## Шаг 2. База D1 и хранилище KV

```bash
npx wrangler d1 create huntback
npx wrangler kv namespace create KV
```

Каждая команда напечатает блок с идентификатором. Впишите их в
`worker/wrangler.toml` вместо заглушек:

```toml
[[d1_databases]]
database_id = "сюда id из первой команды"

[[kv_namespaces]]
id = "сюда id из второй команды"
```

Затем создайте таблицы:

```bash
npm run migrate          # применит worker/migrations/ к базе в облаке
```

**Как понять, что получилось:**

```bash
npx wrangler d1 execute huntback --remote \
  --command "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
```

Должно перечислить девять таблиц: `analyses`, `config`, `documents`, `facts`,
`opportunities`, `profiles`, `runs`, `usage_log`, `users`.

## Шаг 3. Очередь (только если берёте платный план)

Включите Workers Paid в дашборде, затем:

```bash
npx wrangler queues create huntback-runs
```

**Как понять, что получилось:** `npx wrangler queues list` показывает
`huntback-runs`.

## Шаг 4. Первый деплой — чтобы узнать свой адрес

Секреты ещё не заведены, приложение пока не заработает — деплой нужен только
затем, чтобы Cloudflare выдал адрес, который дальше пойдёт в Google.

```bash
npm run deploy           # соберёт SPA и задеплоит воркер вместе с ней
```

В конце выведется адрес вида `https://huntback-api.ваш-поддомен.workers.dev`.

Впишите его в `worker/wrangler.toml`:

```toml
[vars]
APP_ORIGIN = "https://huntback-api.ваш-поддомен.workers.dev"
```

Это важно: из `APP_ORIGIN` собирается `redirect_uri` для Google. Если он не
совпадёт с тем, что вы укажете в Google Cloud, вход будет падать с
`redirect_uri_mismatch`.

**Как понять, что получилось:** адрес открывается и показывает экран входа
Huntback. Кнопка «Войти через Google» пока ведёт в ошибку — это ожидаемо.

## Шаг 5. OpenAI: ключ проекта и лимит расходов

1. `platform.openai.com` → **Projects** → создайте **отдельный проект**
   («Huntback»). Отдельный, а не общий: так расход виден по этому приложению, и
   отзыв ключа не ломает ничего другого (§4.3.1).
2. Внутри проекта → **API keys** → создайте ключ. Скопируйте, он показывается
   один раз.
3. **Limits** → поставьте месячный **spend limit** (например $20) и включите
   алерты. Это последний рубеж поверх лимита внутри приложения.
4. Проверьте, что модели из конфига доступны вашему аккаунту:

```bash
curl -s https://api.openai.com/v1/models \
  -H "Authorization: Bearer ВАШ_КЛЮЧ" | grep -o '"id": *"gpt-[^"]*"' | sort -u
```

Приложение по умолчанию просит `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`
(`core/src/config.ts`). **Если этих имён в списке нет — каждый AI-вызов вернёт
ошибку.** Тогда либо поменяйте имена в конфиге, либо скажите мне, какие модели у
вас есть, и я поправлю.

5. Заведите секрет:

```bash
npx wrangler secret put OPENAI_API_KEY
```

**Как понять, что получилось:** `npx wrangler secret list` показывает
`OPENAI_API_KEY`. Само значение не покажет никогда — так и должно быть.

## Шаг 6. Ключ шифрования токенов

Приложение хранит долгий токен доступа к вашему Google-диску в базе в
зашифрованном виде. Ключ шифрования — отдельный секрет:

```bash
openssl rand -base64 32 | npx wrangler secret put TOKEN_ENC_KEY
```

**Как понять, что получилось:** `TOKEN_ENC_KEY` появился в
`npx wrangler secret list`.

**Не теряйте этот ключ и не меняйте его просто так:** сменили — все сохранённые
токены Google перестают расшифровываться, и всем пользователям придётся войти
заново.

## Шаг 7. Google Cloud: вход через Google

1. `console.cloud.google.com` → создайте проект «Huntback».
2. **APIs & Services → Library** → включите **Google Drive API**. (Пока
   приложение к Диску не обращается — таблица §11 не реализована, — но scope
   `drive.file` запрашивается при входе, и с включённым API не будет сюрпризов
   в выборе scope.)
3. **APIs & Services → OAuth consent screen**:
   - тип **External**;
   - название приложения, ваша почта для связи;
   - **Scopes** → добавьте `openid`, `.../auth/userinfo.email`,
     `.../auth/userinfo.profile`, `.../auth/drive.file`.
     `drive.file` не относится к sensitive и **не требует верификации Google** —
     именно поэтому ТЗ (§5.2) выбрал его, а не полный доступ к таблицам;
   - режим оставьте **Testing**;
   - **Test users** → добавьте свою почту (и всех, кто будет пробовать; до 100).
4. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - тип **Web application**;
   - **Authorized redirect URIs** → ровно один, ваш адрес из шага 4 плюс путь:
     `https://huntback-api.ваш-поддомен.workers.dev/api/auth/callback`
   - сохраните. Появятся **Client ID** и **Client secret**.
5. Заведите секреты:

```bash
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
```

**Про режим Testing — знайте заранее (§5.2):** в этом режиме refresh-токены
Google **протухают через 7 дней**. То есть примерно раз в неделю придётся
входить заново. Это не поломка и не ошибка настройки. Уйдёт, когда приложение
пройдёт верификацию Google; до тех пор так и будет.

**Как понять, что получилось:** в `npx wrangler secret list` четыре секрета:
`OPENAI_API_KEY`, `TOKEN_ENC_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

## Шаг 9. Проверка по сценарию — что должно работать

Откройте свой адрес и пройдите по порядку. Если шаг не сходится — смотрите
«Частые грабли» ниже.

1. **Вход.** «Войти через Google» → согласие → вернулись в приложение, справа
   вверху ваше имя.
   *Если Google пишет, что приложение не проверено, — это Testing-режим, жмите
   «Дополнительно → Перейти».*
2. **Профиль.** Вставьте резюме. Уйдите со страницы и вернитесь — текст на
   месте (автосохранение через 700 мс).
3. **Аудит профиля** — первый реальный вызов модели. Нажмите «Пересчитать».
   Через 20–60 секунд появятся факты и список правок.
   *Это проверка того, что ключ OpenAI и имена моделей верны.*
4. **Подтвердите факты** галочками. Неподтверждённые не попадут в документы.
5. **Добавьте вакансию** — «Добавить вакансию» → вставьте текст вакансии (не
   ссылку: так надёжнее для первой проверки) → «Распознать» → проверьте поля →
   «Создать место».
6. **Разберите ожидания** — «Разобрать ожидания». Появятся 5–7 ожиданий,
   совпадение в процентах и, если есть, жёсткие блокеры.
7. **Соберите резюме и письмо.** Рядом с текстом появятся замечания проверок.
8. **Расходы** — на вкладке «Расходы» видно, сколько потрачено и на что.
   Если там нули, а операции проходили, — что-то не так с учётом, скажите мне.

## Что заработает, а что нет

**Заработает после этой инструкции:** вход через Google, хранение профиля и
фактов, ручное добавление вакансии по тексту и по ссылке, аудит профиля, разбор
ожиданий с блокерами, резюме под место, письма двух типов, все проверки
документов, swap-тест, учёт расходов, лимиты, экран конфига.

**Не заработает, потому что не реализовано:**

| Что | Почему |
|---|---|
| Google-таблица (§11) | синхронизация не написана; поле `spreadsheet_id` в базе заведено, маршрутов `/api/sheet/*` нет |
| Экспорт DOCX и PDF (§10.5) | не написан; текст можно скопировать руками |
| Отправка письма из интерфейса (§12.2) | не написана; нужен scope `gmail.compose` и верификация Google |
| «Найти места» без платного плана | нужна очередь Cloudflare |

## Частые грабли

| Симптом | Причина и что делать |
|---|---|
| `redirect_uri_mismatch` при входе | `APP_ORIGIN` в `wrangler.toml` не совпадает с Authorized redirect URI в Google. Должны совпадать посимвольно, включая `https://` и отсутствие слэша на конце |
| Вход проходит, но при перезагрузке выкидывает | cookie требует HTTPS. На `workers.dev` и своём домене всё хорошо; по `http://localhost` сессия не встанет |
| Раз в неделю просит войти заново | Testing-режим Google, refresh-токен живёт 7 дней (§5.2). Ожидаемо |
| Аудит падает с ошибкой модели | имён `gpt-5.6-*` нет на вашем аккаунте — см. шаг 5, пункт 4 |
| «Модель сейчас перегружена» | 429 от OpenAI. Приложение уже сделало 3 попытки и деградировало на младшую модель; подождите минуту |
| Ссылка на вакансию не открывается | LinkedIn, Indeed и часть ATS отдают страницу только браузеру. Это не поломка: вставьте текст во второе поле, ветка равноправная (§10.8) |
| Деплой падает на привязке `RUNS` | очередь не создана — шаг 3, либо переходите на вариант без очереди |
| Wrangler не понимает `run_worker_first` в `[assets]` | эту настройку я не смог проверить без аккаунта Cloudflare. Если версия wrangler её не принимает — обновите wrangler (`npm i -D wrangler@latest -w worker`), а если не поможет, скажите мне: разнесу SPA и API на Cloudflare Pages плюс маршрут воркера на `/api/*` |
| Открывается витрина с кнопкой «Открыть демо» вместо входа через Google | задеплоена сборка для Pages. Деплойте через `npm run deploy` — он принудительно гасит флаг витрины |
| На экране «Расходы» нули при работающих операциях | учёт пишется в `usage_log`; проверьте `npx wrangler d1 execute huntback --remote --command "SELECT operation, ok, cost_usd FROM usage_log ORDER BY created_at DESC LIMIT 10"` |

## Свой домен — когда захотите

Не обязателен: на `workers.dev` приложение полноценно работает. Когда добавите:

1. Домен в Cloudflare → **Workers Routes** → привяжите `huntback-api` к
   `huntback.app/*`.
2. Поменяйте `APP_ORIGIN` в `wrangler.toml`.
3. Добавьте новый redirect URI в Google Cloud (старый можно оставить).
4. `npm run deploy`.
