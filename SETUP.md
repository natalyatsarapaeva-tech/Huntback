# Huntback — настройка с нуля, без терминала

Всё делается в браузере: панель Cloudflare, консоль Google Cloud, панель OpenAI
и GitHub. **На вашем компьютере ничего устанавливать не нужно** — ни Node, ни
git, ни wrangler. Деплой делает GitHub Actions по кнопке.

Шаги идут в том порядке, в котором их можно выполнять. После каждого написано
**«как понять, что получилось»** — не идите дальше, пока не сходится.

Там, где надо что-то вписать в файлы репозитория, вы **присылаете мне значение,
и я вписываю**. Сами файлы трогать не нужно.

---

## Чего здесь нет

**Firestore.** Huntback на Firebase не построен: в ТЗ (§4.2.3) Firebase отклонён
целиком — данные реляционные и локальные для одного пользователя, поэтому база
D1, а вход свой, а не Firebase Auth. Firestore нужен трём другим приложениям
семейства (twin, twin-things, Help_me_clean), здесь его не касаемся.

**Платный план Cloudflare.** Он требовался только под очереди, а очередей
больше нет: поиск идёт прямо в запросе и стримит прогресс (§9 в редакции 1.3).
Всё приложение укладывается в бесплатный план.

**Новый аккаунт Cloudflare.** В Cloudflare нет «проектов» — есть **аккаунт**, а
внутри него воркеры, базы, хранилища и домены. Ваш `task-intake-worker`
(обслуживает twin, twin-things, Help_me_clean) — это один воркер в вашем
аккаунте. Huntback станет **вторым, отдельным** воркером там же. Отдельный
воркер и отдельный ключ OpenAI — осознанное требование §4.3.1: у старого
воркера нет авторизации, он защищён только проверкой Origin, а здесь в промптах
резюме.

Платить придётся только OpenAI — $5–9 в активный месяц поиска (§10.9).

## Шаг 1. База данных D1

Панель Cloudflare → слева **Storage & Databases** → **D1 SQL Database** →
**Create database**.

- Имя: `huntback` (ровно так, имя используется в деплое)
- Регион: выберите **Europe** — резюме это персональные данные, и §15.2 требует
  хранить их в ЕС

После создания откройте базу. На вкладке **Settings** есть **Database ID** —
длинная строка из букв и цифр.

**Пришлите мне этот Database ID.** Он не секрет: без API-токена по нему ничего
не сделать, и Cloudflare сама рекомендует держать его в репозитории. Но решение
ваше — если не хотите в публичном репозитории, скажите, придумаем иначе.

**Как понять, что получилось:** в списке D1 есть база `huntback`, таблиц в ней
пока ноль.

## Шаг 2. Хранилище KV

Панель Cloudflare → **Storage & Databases** → **KV** → **Create instance**.

- Имя: любое, например `huntback-kv`

После создания скопируйте **Namespace ID**.

**Пришлите мне Namespace ID.**

Что в нём будет лежать: ваши сессии, короткие ключи к Google-диску и
требования вакансий. Всё с таймером — истекает само.

**Как понять, что получилось:** в списке KV есть ваш namespace.

## Шаг 3. Адрес приложения

Панель Cloudflare → **Compute (Workers)** → справа найдите строку
**workers.dev** с вашим поддоменом (что-то вроде `ntsarapaeva.workers.dev` —
тот же, на котором живёт `task-intake-worker`).

Адрес приложения будет `https://huntback.ntsarapaeva.workers.dev`.

**Пришлите мне ваш поддомен.** Я впишу адрес в настройки: из него собирается
`redirect_uri` для входа через Google, и он должен совпасть посимвольно.

Свой домен не нужен — на `workers.dev` приложение работает полноценно. Домен
можно добавить когда угодно потом.

## Шаг 4. Токен, которым GitHub будет деплоить

Панель Cloudflare → иконка профиля справа вверху → **API Tokens** →
**Create Token**.

**Возьмите готовый шаблон, не собирайте права вручную.** В списке шаблонов
найдите **«Edit Cloudflare Workers»** → **Use template**. В нём уже сложен
набор прав, который Cloudflare сама считает нужным для деплоя воркера —
включая те, без которых не проходит загрузка статики, а их из головы не
угадать.

К шаблону добавьте одну строку в разделе Permissions:

| Тип | Что | Уровень |
|---|---|---|
| Account | D1 | Edit |

Account Resources — ваш аккаунт. Создайте токен и **сразу скопируйте** — он
показывается один раз.

Там же понадобится **Account ID**: панель Cloudflare → **Compute (Workers)** →
справа внизу **Account ID**.

Теперь положите оба значения в GitHub:

Репозиторий `huntback` → **Settings** → **Secrets and variables** → **Actions**
→ **New repository secret**. Добавьте два:

| Имя | Значение |
|---|---|
| `CLOUDFLARE_API_TOKEN` | токен из этого шага |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID |

**Как понять, что получилось:** в списке Actions secrets видны оба имени
(значения GitHub не покажет — так и должно быть).

## Шаг 5. OpenAI: ключ проекта и лимит расходов

`platform.openai.com` → **Projects** → создайте **отдельный проект**
(«Huntback»). Отдельный, а не общий: так расход видно по этому приложению, и
отзыв ключа не ломает ничего другого.

1. Внутри проекта → **API keys** → создайте ключ, скопируйте (показывается
   один раз).
2. **Limits** → поставьте месячный **spend limit** (например $20) и включите
   алерты. Это последний рубеж поверх лимита внутри приложения.
3. **Проверьте, что нужные модели вам доступны.** Приложение просит
   `gpt-5.6-sol`, `gpt-5.6-terra` и `gpt-5.6-luna`. Откройте
   `platform.openai.com/docs/models` и найдите их в списке доступных вашему
   аккаунту. **Если их там нет — каждый вызов модели вернёт ошибку.** Тогда
   пришлите мне список того, что есть, и я поправлю конфиг.

Ключ пока просто сохраните — впишете его на шаге 8, когда воркер появится.

## Шаг 6. Первый деплой

GitHub → репозиторий `huntback` → вкладка **Actions** → слева **Deploy** →
кнопка **Run workflow** → **Run workflow**.

Это сработает только после того, как я впишу идентификаторы из шагов 1–3, так
что сначала пришлите их мне и дождитесь моего «готово».

Что произойдёт: соберётся интерфейс, прогонятся тесты, создадутся девять таблиц
в базе и задеплоится воркер вместе с интерфейсом.

**Как понять, что получилось:**

- в Actions прогон **Deploy** зелёный;
- `https://huntback.ntsarapaeva.workers.dev` открывается и показывает экран
  входа Huntback. Кнопка «Войти через Google» пока ведёт в ошибку — это
  ожидаемо, вход настраивается на шаге 7;
- в панели Cloudflare → D1 → `huntback` → **Tables** девять таблиц: `analyses`,
  `config`, `documents`, `facts`, `opportunities`, `profiles`, `runs`,
  `usage_log`, `users`.

## Шаг 7. Google Cloud: вход через Google

Консоль Google в 2025 году переехала: то, что раньше было мастером «OAuth
consent screen», теперь разнесено по страницам раздела **Google Auth
Platform**. Ниже — по нынешнему расположению.

**1.** `console.cloud.google.com` → селектор проекта сверху → **New Project** →
название «Huntback» → Create. **Дождитесь переключения на новый проект** и
проверьте его в селекторе: остаться в чужом проекте — самая частая потеря часа.

**2. APIs & Services → Library** → найдите **Google Drive API** → **Enable**.
(Приложение к Диску пока не обращается — таблица §11 не реализована, — но scope
`drive.file` запрашивается при входе.)

**3. Google Auth Platform → Branding** (или **Get started**, если раздел ещё не
создан): название приложения `Huntback`, почта поддержки и контакт разработчика
— ваши. Сохраните.

**App name заполните обязательно.** Именно его человек видит на экране согласия
Google: «Войти в приложение …». Если поле пустое, Google подставляет домен, и
вместо «Huntback» ваши друзья увидят `huntback.ntsarapaeva.workers.dev` — это
работает, но выглядит как подозрительная ссылка.

**4. Google Auth Platform → Audience:**
- **Audience type**: **External**
- **Publishing status**: оставьте **Testing**
- **Test users** → **Add users** → впишите свою почту → **Save**

Это отдельная страница, а не шаг мастера. **Без неё вход отвечает `403:
access_denied`** — Google пускает только перечисленных здесь.

Два ограничения, о которых Google сообщает уже после ошибки:

- адрес должен быть **существующим Google-аккаунтом**. Опечатка даёт
  «Ineligible accounts not added» — Google не принимает адреса, за которыми
  нет аккаунта;
- **аккаунт-владелец проекта** добавить, скорее всего, не получится: он уже
  допущен и в списке не нужен. Если Google отказывается добавить именно ваш
  собственный адрес — значит добавлять нечего, и `access_denied` означал, что
  в браузере вы вошли под другим аккаунтом.

**5. Google Auth Platform → Data access** → **Add or remove scopes** →
отметьте четыре:
- `openid`
- `.../auth/userinfo.email`
- `.../auth/userinfo.profile`
- `.../auth/drive.file`

→ Update → Save. `drive.file` не относится к sensitive и **не требует
верификации Google** — именно поэтому §5.2 выбрал его, а не полный доступ к
таблицам.

**6. APIs & Services → Credentials → Create Credentials → OAuth client ID:**
- Application type: **Web application** ← критично, не Desktop app
- **Authorized redirect URIs** → **Add URI** → вставьте целиком:

```
https://huntback.ntsarapaeva.workers.dev/api/auth/callback
```

- Create → откроется окно с **Client ID** и **Client Secret**. Скопируйте оба.

**Про режим Testing — знайте заранее (§5.2):** refresh-токены Google в нём
**протухают через 7 дней**, то есть примерно раз в неделю придётся входить
заново. Это не поломка и не ошибка настройки. Уйдёт, когда приложение пройдёт
верификацию Google.

**Как понять, что получилось:** в списке Credentials есть клиент типа Web
application, а в Audience — ваша почта среди Test users.

## Шаг 8. Секреты приложения — в панели воркера

Теперь воркер существует, и в него можно вписать секреты.

Панель Cloudflare → **Compute (Workers)** → `huntback` → **Settings** →
**Variables and Secrets** → **Add**. Для каждого выбирайте тип **Secret**
(не Text — иначе значение будет видно в панели):

| Имя | Значение | Откуда |
|---|---|---|
| `OPENAI_API_KEY` | ключ OpenAI | шаг 5 |
| `GOOGLE_CLIENT_ID` | Client ID | шаг 7 |
| `GOOGLE_CLIENT_SECRET` | Client secret | шаг 7 |
| `TOKEN_ENC_KEY` | см. ниже | сгенерировать |

**`TOKEN_ENC_KEY`** — ключ, которым шифруется ваш долгий токен доступа к
Google-диску перед записью в базу. Нужны 32 случайных байта в base64. Без
терминала это можно получить так: откройте в браузере консоль разработчика
(F12 → Console) на любой странице и вставьте:

```js
btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(32))))
```

Скопируйте выведенную строку — это и есть значение.

**Не теряйте этот ключ и не меняйте его просто так:** сменили — все сохранённые
токены Google перестают расшифровываться, и придётся входить заново.

После добавления всех четырёх нажмите **Deploy** в панели воркера (или ещё раз
запустите workflow **Deploy** в GitHub — любой способ подхватит секреты).

**Как понять, что получилось:** в разделе Variables and Secrets четыре записи,
у каждой тип Secret и значение скрыто.

## Шаг 9. Проверка по сценарию

Откройте свой адрес и пройдите по порядку. Если что-то не сходится — смотрите
«Частые грабли».

1. **Вход.** «Войти через Google» → согласие → вернулись в приложение, справа
   вверху ваше имя.
   *Google предупредит, что приложение не проверено — это Testing-режим,
   жмите «Дополнительно → Перейти».*
2. **Профиль.** Вставьте резюме. Уйдите со страницы и вернитесь — текст на
   месте (автосохранение через 700 мс).
3. **Аудит профиля** — первый реальный вызов модели. «Пересчитать». Через
   20–60 секунд появятся факты и список правок.
   *Это и есть проверка того, что ключ OpenAI и имена моделей верны.*
4. **Подтвердите факты** галочками. Неподтверждённые не попадут в документы.
5. **Добавьте вакансию** → вставьте **текст** вакансии (не ссылку: для первой
   проверки надёжнее) → «Распознать» → проверьте поля → «Создать место».
6. **Разберите ожидания.** Появятся 5–7 ожиданий, совпадение в процентах и,
   если есть, жёсткие блокеры.
7. **Соберите резюме и письмо.** Рядом с текстом появятся замечания проверок.
8. **Найти места** — самая длинная операция. Под шапкой появится полоса с
   этапом, счётчиком направлений («2 из 4») и остатком времени. Прогон идёт от
   минуты до нескольких, смотря сколько ролей в периметре и какой охват.
   *Вкладку можно закрыть — найденное всё равно допишется в базу.*
9. **Расходы.** Видно, сколько потрачено и на что. Если там нули, а операции
   проходили — что-то не так с учётом, скажите мне.

## Что заработает, а что нет

**Заработает:** вход через Google, хранение профиля и фактов, ручное добавление
вакансии по тексту и по ссылке, поиск мест по кнопке с полосой прогресса, аудит
профиля, разбор ожиданий с блокерами, резюме под место, письма двух типов, все

| Что | Почему |
|---|---|
| Google-таблица (§11) | синхронизация не написана; поле `spreadsheet_id` в базе заведено, маршрутов `/api/sheet/*` нет |
| Экспорт DOCX и PDF (§10.5) | не написан; текст можно скопировать руками |
| Отправка письма из интерфейса (§12.2) | не написана; нужен scope `gmail.compose` и верификация Google |

## Частые грабли

| Симптом | Причина и что делать |
|---|---|
| `redirect_uri_mismatch` при входе | адрес в настройках приложения не совпадает с Authorized redirect URI в Google. Должны совпадать посимвольно, включая `https://` и отсутствие слэша на конце |
| «Ineligible accounts not added» при добавлении тестировщика | за этим адресом нет Google-аккаунта (чаще всего опечатка), либо это аккаунт-владелец проекта — он допущен и так, добавлять его не нужно |
| На экране согласия Google вместо «Huntback» показан домен | не заполнено App name в **Google Auth Platform → Branding** |
| `403: access_denied`, «им могут пользоваться только одобренные тестировщики» | вашего аккаунта нет в списке тестировщиков: **Google Auth Platform → Audience → Test users → Add users**. Адрес должен совпадать с тем, которым вы входите — если в браузере несколько Google-аккаунтов, выберите нужный. Применяется иногда через минуту |
| `401: invalid_client` от Google | Google не принял идентификатор клиента. Приложение теперь проверяет это само и вместо редиректа показывает страницу с причиной — откройте `/api/auth/start` и прочитайте, что там написано. Три причины по частоте: секреты ещё не заданы (шаг 8); `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` перепутаны местами; клиент создан с типом «Desktop app» вместо «Web application» |
| Прогон Deploy падает на миграциях | не вписан Database ID из шага 1, либо у токена нет права D1:Edit |
| Прогон Deploy падает на `deploy` с `Authentication error [code: 10000]` на `assets-upload-session` | у токена не хватает прав на загрузку статики. Пересоздайте его из шаблона **«Edit Cloudflare Workers»** плюс D1:Edit — шаг 4. Собранный вручную минимальный набор прав здесь не работает |
| В логе `Unexpected fields found in assets field: "run_worker_first"` | старый wrangler. Версия зафиксирована в `worker/package.json`, и workflow вызывает её напрямую; если предупреждение вернулось — значит wrangler откуда-то подставился другой, скажите мне |
| Раз в неделю просит войти заново | Testing-режим Google, refresh-токен живёт 7 дней (§5.2). Ожидаемо |
| Аудит падает с ошибкой модели | имён `gpt-5.6-*` нет на вашем аккаунте — см. шаг 5, пункт 3 |
| «Модель сейчас перегружена» | 429 от OpenAI. Приложение уже сделало 3 попытки и деградировало на младшую модель; подождите минуту |
| Ссылка на вакансию не открывается | LinkedIn, Indeed и часть ATS отдают страницу только браузеру. Это не поломка: вставьте текст во второе поле, ветка равноправная (§10.8) |
| Поиск идёт долго, полоса стоит на одном направлении | так и есть: один поисковый запрос с веб-поиском занимает под минуту. Полоса ползёт между событиями, но не перескакивает вперёд — она показывает реальное положение, а не анимацию |
| Открывается витрина с кнопкой «Открыть демо» вместо входа | это страница GitHub Pages, а не приложение. Приложение — на адресе `workers.dev` |
| Wrangler не понимает `run_worker_first` в `[assets]` | эту настройку я не смог проверить без аккаунта Cloudflare. Если прогон Deploy на ней падает — скажите, разнесу интерфейс и API иначе |

## Свой домен — когда захотите

Не обязателен. Когда добавите:

1. Домен в Cloudflare → **Compute (Workers)** → `huntback` → **Settings** →
   **Domains & Routes** → добавьте свой домен.
2. Пришлите мне его — поменяю адрес в настройках приложения.
3. Добавьте новый redirect URI в Google Cloud (старый можно оставить).
4. Запустите workflow **Deploy**.

## Если однажды захотите работать локально

Это не нужно ни для чего из перечисленного выше — только если захотите сами
править код и проверять правки у себя. Тогда: установите
[Node.js 22+](https://nodejs.org) и [git](https://git-scm.com), склонируйте
репозиторий (`git clone https://github.com/natalyatsarapaeva-tech/huntback`),
и в появившейся папке — «корне репозитория» — работают `npm install`,
`npm test`, `npm run dev`.
