# План работ: ноябрь 2026 — коуч, ревью документов, разбор с исправлениями

Цель: пользователь с минимальными затратами времени готовит резюме и письма на
все интересующие вакансии. Каждый пункт ниже — отдельный коммит.

## 1. Поиск вакансий в LinkedIn

- Отдельный проход `linkedin` в прогоне поиска: веб-поиск только по
  `linkedin.com`, промпт просит адреса вида `/jobs/view/<id>`.
- Варианты названий ролей (ядро, без модели): синонимы по-английски и на языке
  страны (COO ↔ Chief Operating Officer ↔ Head of Operations ↔ driftchef).
  Подставляются в промпты всех проходов как готовые запросы.
- Нормализация ссылок LinkedIn (ядро): `currentJobId=…`, мобильные и
  локализованные адреса → `https://www.linkedin.com/jobs/view/<id>/`;
  ссылки на компанию/посты/поиск не считаются вакансией. Дедуп по id вакансии.
- Готовые ссылки «искать в LinkedIn самому» по каждому направлению × география
  с фильтрами «за неделю» и «Director/Executive» — без парсинга LinkedIn.
- Загрузка текста вакансии по ссылке LinkedIn: извлечение блока описания из
  гостевой страницы; чистка мусора из скопированного текста LinkedIn.
- Пакетный импорт: несколько текстов вакансий за раз (разделитель `---`).

## 2. Разбор банка фактов — автоматизированный

- Аудит возвращает для каждого факта подсказку: `question` (наводящий вопрос,
  когда число или масштаб вероятно есть, но не названы) или `rewrite`
  (предложенная формулировка «действие → как → результат»), либо `ok`.
- Экран «Разбор фактов» по одному: слева цитата из резюме, справа предложение;
  кнопки «Принять», «Принять формулировку», «Ответить» (ответ → модель
  переписывает факт с этим числом), «Править», «Отклонить». Клавиатура.
- Ответы пользователя хранятся в факте (`user_input`) и считаются источником —
  правило единственного источника не нарушается.

## 3. Коуч: «провести за руку к идеальному резюме»

- Повестка коуча считается в ядре без модели: факты без числа в последних
  ролях, пустые поля масштаба/языков/права на работу, перерывы без причины,
  роли без достижений, совпадение с периметром.
- Чат с наводящими вопросами по одной теме за раз; ответ модели структурирован:
  реплика + предлагаемые изменения (новые факты, правки фактов, поля профиля),
  которые применяются одной кнопкой. История хранится в D1.
- По завершении — «мастер-резюме»: базовое резюме под периметр, прошедшее
  цикл писатель → проверяющий.

## 4. Разбор вакансии: «40% — это формулировки, а не опыт»

- Для каждого неполного/закрытого ожидания модель указывает причину:
  `wording` (опыт есть, нет формулировки работодателя), `missing_fact`
  (вероятно есть, но не записано — вопрос пользователю), `real_gap`.
- Исправление: новая формулировка факта под термины вакансии либо вопрос.
- Потенциал совпадения считает ядро: «сейчас 40% → 72% после 3 правок».
- Применение формулировки — без модели; ответ на вопрос → новый факт и
  дешёвая переоценка только этого ожидания.

## 5. Документы: писатель → проверяющий → писатель → проверяющий

- Детерминированные детекторы в ядре: ИИ-измы (delve, spearheaded, leverage,
  testament, seamless…), плотность тире, повторы между буллитами, штампы.
- Агент-проверяющий: дублирование, фактические ошибки против банка фактов,
  штампы, ИИ-измы, притянутость за уши. Вердикт и список замечаний с цитатой
  и правкой.
- Цикл: черновик → ревью 1 → переписывание → ревью 2 → (если есть замечания)
  финальная правка. Отчёт о ревью виден рядом с документом.
- Прогресс генерации стримится (как поиск), чтобы 2–3 минуты не выглядели
  зависанием.

## 6. Пакетная подготовка

- «Подготовить документы» для выбранных мест: текст вакансии → разбор →
  формулировки → резюме → письмо, очередью с прогрессом.
- Готовые документы: копирование, печать/PDF, скачивание .txt.

## 7. Пользовательское тестирование

- Полный стек локально: воркер в `wrangler dev` с локальными D1/KV и
  заглушкой OpenAI (сценарные ответы, включая черновики с ошибками, чтобы
  цикл ревью реально работал).
- Сценарий персоны (Playwright): онбординг → разбор фактов → коуч → поиск →
  импорт из LinkedIn → разбор с исправлениями → пакетная подготовка →
  выгрузка. Замер кликов и времени, список найденных проблем, исправления.
