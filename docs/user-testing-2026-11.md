# Пользовательское тестирование — ноябрь 2026

Цель: убедиться, что кандидат с минимальными затратами времени готовит резюме и
письма на все интересующие вакансии.

## Как тестировалось

Ключей OpenAI, Google и Cloudflare у сборки нет, поэтому тест шёл на **настоящем
воркере** (`wrangler dev`, локальные D1 и KV, все миграции) против **заглушки
OpenAI**, которая строит ответы из самого промпта (`scripts/e2e/`). Вся логика
воркера и ядра — проверка цитат, чисел, блокеров, цикл ревью, дедуп — работала
по-настоящему; подделано только содержание ответов модели. В заглушку заложены
ошибки, которые система обязана поймать.

Персона: руководитель операций, 12 лет опыта, две роли, резюме из 10 строк;
ищет «Head of Operations; VP Supply Chain» в Швеции и Германии. Три вакансии
скопированы «из LinkedIn» вместе с мусором интерфейса (Easy Apply, «48
applicants», Show more); одна требует свободный немецкий.

Два прогона:

- `npm run e2e:smoke` — 29 проверок API по всем новым функциям;
- `npm run e2e:journey` — браузер (Playwright), пустой аккаунт → документы,
  с подсчётом кликов и времени.

Плюс `npm run check:layout` на 375 / 414 / 768 / 1280 px по всем новым экранам.

## Итог сценария

| Этап | Клики | Что происходит |
|---|---|---|
| Резюме + периметр + аудит | 6 | вставить текст, роли, страны |
| Разбор фактов по одному | 10 | 8 фактов: принять формулировку, ответить на 2 вопроса, подтвердить |
| «Что снимает сомнения» | 9 | право на работу уже подставлено из географии, добавить языки и команду |
| Коуч, 3 ответа | 9 | каждый ответ → предложение «Apply» |
| Найти и вставить 3 вакансии | 7 | ссылки поиска LinkedIn → «Paste several» → одно поле с `---` |
| **Подготовить документы на все** | **1** | разбор → формулировки → резюме → письмо, каждое с двумя ревью |
| Ответить на вопросы + пересобрать | 7 | общий список вопросов всех мест |
| Открыть, скопировать | 3 | отчёт ревью, Copy / Print-PDF / .txt |
| **Всего** | **52** | ошибок JS: 0 |

Результат: резюме и письмо на 2 из 3 вакансий; третья честно пропущена —
«German is not in your profile, but the role requires it (open the place to
decide)». Совпадение на одном месте поднялось 57% → 71% формулировками и до
93% после одного ответа.

### Оценка реального времени

Время с заглушкой не показательно, поэтому оценка по типичной длительности
вызовов модели:

- **один раз:** онбординг и разбор фактов — 10–15 минут; коуч — ещё 10;
- **на каждые 10 вакансий:** скопировать тексты — 5 минут; «Prepare documents»
  — около 25 минут **без участия человека** (2 места параллельно, по 4–6
  вызовов модели на документ); ответить на вопросы — 3–5 минут;
- **стоимость** по `TYPICAL_COST`: около $0,15–0,20 за место с двумя ревью —
  при лимите $15 это 70+ мест в месяц.

## Что тест нашёл и что исправлено

Существенные:

1. **Ни одного документа при отчёте «готово для 3 мест».** Персона не заполнила
   право на работу (онбординг только перечислял такие поля), каждое место
   получило блокер «unknown», пакетная подготовка всё пропустила — а итоговое
   сообщение сообщило об успехе. Исправлено втрое: шаг «сомнения» стал
   короткой формой с подставленными из географии странами; перед подготовкой
   проверяется, для каких стран право на работу не указано; итог говорит
   «готово N из M» и какое одно поле разблокирует остальное.
2. **Факт без числа считался «с числом».** `metric_value: null` из ответа модели
   превращался в 0 (`Number(null) === 0`), и каждый факт выглядел
   квантифицированным. Тихо отключало аудит «добавьте число», повестку коуча и
   вопросы разбора — в проде, не только в тесте. Исправлено, есть тест.
3. **Устаревшие блокеры.** Карточка места показывала блокеры на момент разбора;
   заполненное право на работу не снимало «unknown», пока место не разобрать
   заново. Теперь блокеры пересчитываются правилами при каждом открытии.
4. **Выдуманное число в вопросе.** Если модель предлагала формулировку с
   числом, которого нет в фактах, ядро превращало её в вопрос — но цитировало
   выдумку: «Верно ли, что вы руководили 140 людьми?». Теперь вопрос нейтральный.
5. **Письмо блокировалось собственной просьбой:** «a 20-minute call» считалось
   непроверенным числом. Длительность встречи больше не проверяется.

Мелкие: префилл права на работу не срабатывал, если шаг фактов завершался сам;
галочка «✓» у документа с блокирующими замечаниями (теперь «⚠ check
remarks»); колонка места вылезала за экран на 375 px; чекбоксы фактов и ссылка
в тексте меньше 44 px; на телефоне «Spending» обрезался до «Sp»; дедуп внутри
одного прогона поиска сравнивал название компании с ключом и не срабатывал;
после «Clear profile» повторный онбординг ничего не сохранял (строки профиля
не было).

## Что проверено автоматикой

- антигаллюцинация: выдуманная цитата аудита отброшена; выдуманная цитата
  проверяющего отброшена; формулировка с выдуманным числом стала вопросом;
- цикл ревью: черновик с «Spearheaded a seamless…» и повтором → проверяющий
  возвращает → переписано → второе ревью → ИИ-изм исчез; стадии видны в статусе;
- коуч: ответ без числа не становится фактом; применённое предложение
  меняет профиль или банк фактов, и тема уходит из повестки;
- LinkedIn: ссылка с трекингом и поддоменом → `linkedin.com/jobs/view/<id>/`;
  страница поиска вместо вакансии отброшена; одна вакансия из двух проходов —
  одно место; мусор интерфейса из вставленного текста вычищен.

## Что осталось и что стоит сделать дальше

- **Проверить на реальной модели.** Заглушка подтверждает механику, но не
  качество текста. Первым делом после деплоя — 3–5 настоящих вакансий и
  чтение отчётов ревью: находит ли проверяющий то, что нашёл бы человек.
- **Повторяющиеся вопросы.** На трёх местах набралось 12 вопросов, часть по
  смыслу одинаковая («stakeholder management» в двух вакансиях). Ответ уходит
  в банк фактов и поможет при следующем разборе, но сейчас засчитывается
  только месту, где задан. Следующий шаг — группировать похожие вопросы и
  засчитывать ответ всем местам сразу.
- Вопросы мест с жёстким блокером можно не показывать в общем списке.
- Экспорт в DOCX (сейчас — копирование, печать в PDF и .txt).
- Финальный черновик после второго переписывания проверяет только код, без
  третьего ревью модели — намеренно, чтобы цикл заканчивался; остаток
  замечаний второго ревью виден в отчёте.
