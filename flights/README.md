# Поиск перелётов с умными пересадками

Ищет перелёты сразу в несколько аэропортов, прибавляет к каждому варианту
дорогу до конечного города и отбрасывает неудобные пересадки. Варианты
ранжируются по цене и времени в пути вместе.

Первый пресет — `presets/valencia-december.json`:

> перелёт из Копенгагена или Мальмё на 8–10 дней с вылетом 20–25 декабря в
> Валенсию напрямую или в Барселону, Мадрид, Аликанте плюс поезд до Валенсии;
> дневная пересадка не длиннее 3,5 ч, ночная не короче 10 ч.

В интерфейсе всё это меняется: города вылета добавляются и убираются, аэропорты
прилёта — тоже, вместе с трансфером и поездом до конечного города; длительности
поездки, пересадок, ночное окно, цена часа и запас на аэропорт — ползунками.
Ползунки, которым не нужны новые данные, пересчитывают выдачу сразу.

## Запуск

Нужен Node 22.6+ и больше ничего: зависимостей нет.

```bash
cd flights
npm start                      # http://localhost:5178
npm run search -- --from CPH,MMX   # то же в терминале
npm test
```

Без ключей работают только **демо-данные**: рейсы выдуманы, интерфейс
об этом предупреждает. Для настоящих цен задайте ключ хотя бы одного источника:

```bash
SERPAPI_KEY=... DUFFEL_TOKEN=... npm start
npm run search -- --from CPH,MMX --provider serpapi --provider duffel
```

| Источник | Что даёт | Ключ |
|---|---|---|
| **Google Flights через SerpAPI** | Почти всё, что видят Skyscanner и Anywayanyday, включая лоукостеры, с точным временем каждого сегмента | [serpapi.com](https://serpapi.com/users/sign_up), бесплатно 250 запросов/мес |
| **Duffel** | Живые цены авиакомпаний, которые можно купить; без Ryanair и части лоукостеров | [duffel.com](https://app.duffel.com/join), в тестовом режиме бесплатно |

Один поиск по пресету — это **112 запросов к источнику**: 2 города вылета ×
4 аэропорта прилёта × (6 дат туда + 8 дат обратно); с одним Копенгагеном — 56.
Ответы кэшируются на 6 часов в `flights/.cache`. Перед поиском внизу экрана
видно, сколько из запросов новые, то есть платные. Ползунки пересадок, цены
часа, поездов и числа пересадок новых запросов не требуют и пересчитывают
выдачу сразу. Новые запросы нужны только при смене дат, длительности поездки,
городов или источника.

## Почему нет прямого поиска на Skyscanner, Anywayanyday и Ticket.se

У них нет открытого API. Партнёрский API Skyscanner выдают только сайтам с
трафиком, у Anywayanyday и Ticket.se публичного API нет совсем, а парсинг их
сайтов запрещён условиями использования и упирается в капчу. Поэтому цены
берутся из Google Flights и Duffel, а к каждому варианту приложение даёт
ссылки на тот же рейс в Skyscanner, Google Flights и Anywayanyday:
там его можно сверить и купить. Ticket.se не принимает параметры в ссылке,
поэтому ссылка ведёт на его форму поиска.

## Как работают правила

**Пересадка ночная**, если на ночное окно (по умолчанию 23:00–06:00 по
местному времени аэропорта пересадки) приходится хотя бы 60 минут. Ночная
пересадка должна длиться не меньше 10 часов (время доехать до отеля и
выспаться), дневная — не больше 3,5 часа. Любая стыковка — не короче 45 минут,
смена аэропорта (LGW → LHR) запрещена. Всё это меняется в форме.

**Дорога до Валенсии** считается для каждого рейса отдельно: 40 минут на
выход из аэропорта, трансфер до вокзала, ожидание в половину интервала между
поездами, сам поезд. Если прилёт позже последнего поезда, добавляется
ночёвка (90 €) и утренний поезд. На обратном пути — в аэропорту за 2 часа до
вылета; если для этого пришлось бы ехать раньше первого поезда, выезд
накануне вечером и ночёвка. Цены и время поездов в пресете ориентировочные,
их можно поправить в форме («Поезда, трансферы…»).

**Ранжирование**: деньги + часы в пути × цена часа (по умолчанию 15 €/ч).
При цене часа 0 сортировка идёт только по цене. Отдельно помечены самый
дешёвый вариант, самый быстрый и варианты «без компромисса»: для них нет
другого варианта, который был бы одновременно дешевле и быстрее.

**Open-jaw**: туда можно лететь в Мадрид, а обратно из Барселоны, и
улететь из Копенгагена, а вернуться в Мальмё. Галочки «улетать обратно из
того же аэропорта» и «возвращаться в тот же аэропорт» это запрещают.

Под каждой выдачей видно, сколько вариантов просмотрено и сколько отброшено
по каждому правилу. Если ничего не нашлось, по этим цифрам понятно, какое
условие ослабить.

## Ограничения

- Цена — сумма двух билетов в одну сторону. Туда-обратно одним билетом
  бывает дешевле, поэтому у каждого варианта есть ссылка «купить парой».
- Два отдельных билета не защищены от опоздания на стыковку между ними.
  Внутри одного билета (одна выдача Google или Duffel) защищены.
- Демо-провайдер не учитывает часовые пояса, настоящие источники учитывают.

## Устройство

```
src/types.ts       запрос, рейс, правила
src/layover.ts     дневная/ночная пересадка и её проверка
src/ground.ts      дорога от аэропорта до конечного города и обратно
src/plan.ts        оценка ноги, сборка поездок, Парето-фронт
src/search.ts      план запросов, кэш, параллельность, дедуп между источниками
src/links.ts       ссылки на агрегаторы
src/providers/     mock, serpapi, duffel
src/server.ts      HTTP-сервер для интерфейса
src/cli.ts         то же из терминала
public/index.html  интерфейс
presets/           готовые запросы
```

Новый маршрут — это новый JSON в `presets/` по образцу валенсийского.
